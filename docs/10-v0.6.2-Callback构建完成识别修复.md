# v0.6.2 — Plugin Callback 成功但控制台未加载完成

## 现场复现

- Plugin Jenkins #1: Manual Trigger，已生成关联的 #2 Manual Callback。
- Jenkins #2 页面为绿色 SUCCESS；Console Output 末行 `Finished: SUCCESS`。
- 旧工具仍轮询 `Build #2 状态尚未确认`，未进入 Artifact / GMX。

## 修复

1. `consoleText` 200 + `DOMContentLoaded` 并非内容已经完整。Playwright 显式等待**当前控制台最后一行**匹配 `Finished: SUCCESS / FAILURE / ABORTED / UNSTABLE / NOT_BUILT`。匹配时立即返回当前构建的真实结果。默认最多等待 10 秒，通过 `jenkins.console_settle_seconds` 控制。
2. 控制台暂未给出终态时，访问 **当前编号 Build 的标题状态区域**。兼容 Jenkins 通过 SVG `<use href=".../status/blue.svg#blue">` 或 `icon-success` 等表达结果的情况。
3. 控制台与状态图标都没有权威终态时继续监控，不误用其他历史 Build 的绿色状态。失败明确返回 FAILURE/ABORTED，禁止把失败认作成功。
4. 复用已有任务已保存的 #1/#2 Build Number；无需再次执行 Git push / Build，支持 Resume。
5. 日志打印 `Console 最后一行确认` 或 `页面标题图标确认终态`，方便排查。

## 验证边界

全部测试通过的是离线模拟和本地测试；没有内网 Jenkins/SSO 的访问条件，因此真实 Jenkins 定制 UI 仍需用户在 Mac 上联调。
