# 企业内网联调清单（真实环境验证前不应宣称生产可用）

以下均需在用户授权的 Mac 与公司网络中完成；没有凭据时只能在离线模拟环境完成代码回归。

## 1. 安装与身份

- [ ] 公司 Nexus PyPI group URL、公司 CA 证书和访问权限确认，`./install.sh` 可完成（没有公网回退）。
- [ ] 企业 Chrome/Edge 允许 Playwright 启动；公司 SSO cookie/session 可以按 IT 政策安全复用。
- [ ] `GITHUB_TOKEN` 能访问并 Push 两个目标仓库；如需 SSO/管理员批准，已完成相关授权。
- [ ] `./bootstrap.sh` 运行所需 Node/Ruby/CocoaPods 或内部 CLI 等依赖已按 GMX README/CI 要求准备好。

## 2. Plugin Job

- [ ] 创建 `release/1.3.<时间戳>` 后实际 Jenkins Job 路径与 `release_1_3_<时间戳>` 一致。
- [ ] 首次 `Build` 和随后 `Build with Parameters` UI 控件可被唯一识别，且不会在未经确认的情况下重复触发。
- [ ] 参数默认值对应正确的目标源分支/Commit，确认是否存在可导致构建其他 PR 的默认参数（截图中的参数曾显示其他 PR）。
- [ ] `consoleText` 或 Build status 实际页面允许浏览器读取最终状态；UI 若不同需更新选择器。
- [ ] `#2 Manual Trigger → #3 Manual Callback` 关联逻辑（若 Jenkins 实际采用）能够定位正确 Build。
- [ ] Artifacts 页面内 `build-universal/` 可以枚举两个 tar.gz，且版本一致。必须从本次 SUCCESS Build，不是 Last Successful。

## 3. GMX 文件和 Jenkins

- [ ] `mobile-ci.json` 两项依赖字段结构与截图相符。
- [ ] GMX 目录的 `./bootstrap.sh` 成功完成；两个 lock SHA256 正确，且其他依赖未被意外修改。
- [ ] Commit 前后 Diff 精确匹配；Git Hook 不会制造非预期变更。
- [ ] `upload/<工单编号>-auto<时间戳>` Job URL 实际使用 `%2F` 编码。
- [ ] 新 Job 首次普通 Build 初始化行为已在真实 Jenkins 页面验证。
- [ ] `ENTITIES` 类型（下拉框/文本框）、`SYNC_UPLOAD` 复选框、`CUSTOM_FOLDER` 字段能被 Playwright 正确定位。
- [ ] `BUILD_TYPE`、`SIGNING_REPO_BRANCH` 和其他字段依然采用 Jenkins 默认值。
- [ ] Jenkins SUCCESS 是否包括最终上传操作、如何辨认上传成功日志，确定是否配置 `upload_success_pattern`。

## 4. 故障恢复和多任务

- [ ] 使用非生产/测试分支同时运行两个独立 APP，确认 Git/SSO/Jenkins 的共享限制。
- [ ] 在等待 Jenkins 结果时结束一个 Worker，再 `resume`；不应产生重复 Build。
- [ ] 关闭 VPN 或让 SSO 过期，确认 `NEEDS_ATTENTION`、截图和日志可用。
- [ ] 任务输出没有泄漏 GitHub Token、SSO Cookie 或 Nexus 凭据。
- [ ] 错误后的清理策略（是否保留远端自动分支、构建产物、任务目录）由团队确定；当前工具不会自动删除远端分支。

## 5. 发布门槛

只有完成以上真实环境验证，且实际 GMX Jenkins Build 与上传阶段按预期结束，才应在团队内部标记版本为“企业端到端验收通过”。本地 30 项测试只覆盖通用逻辑和模拟 UI，不能替代 Jenkins 真机测试。
