# Jenkins 403 / Not Found 的有限登录恢复

## 可证实问题

用户任务 `202610111410-e4b939` 的日志指向 Plugin Job，HTTP 403；截图是该任务保存的错误页，不是 Jenkins 地址栏。当前下划线映射确实会把 `release/1.3.202610111410` 映射到 `release_1_3_202610111410`，没有现场证据支持修改此规则。

在未修复的 main 上运行新增 Chromium 用例，复现两个代码缺陷：同域 403/Not Found 页面只有 Sign in 链接时，旧代码跳过认证并直接报“无权”；HTTP 200 的 Oops/Not Found 错误页可被旧代码当成已经发现 Job。未证明用户公司服务器此次实际拒绝的原因；缓存过期是可复现的原因之一，不能把截图当成服务端 ACL 结论。

## 修复范围

- 错误页存在真实、同域 Jenkins 登录入口，且没有明确的非匿名权限拒绝信息时，只尝试一次重新认证；返回精确原 Job URL，不生成或猜测替代路径。
- 明确权限拒绝立即停止；普通或不明原因 403 不循环重试、不盲目清空 Cookie、不绕过权限。重新登录后仍失败，也不认定必然是权限问题。
- HTTP 200 的 Not Found/Access Denied 页面不会通过 Job 就绪检查。404 仍按原有间隔等待分支索引，并受超时限制。
- 同域用户名页、未完成 SSO、错误页不能作为“登录成功”保存缓存。可见浏览器可等待人工 SSO，最多 180 秒。
- Resume 记录来源分支、目标分支与保存的 Job URL。有效配置与保存 URL 不同时给出提示，不修改历史 Job/Build 或已完成步骤。新增日志去除 URL 查询串等敏感内容，不输出密码或 Cookie。
- 沿用浏览器页面交互，没有新增 Jenkins REST API 或服务器权限操作。

## 离线验证

`tests/test_jenkins_access_recovery.py`：10 项，包括真实 Chromium 加载过期 storage_state 后，经 403/Not Found、Sign in 返回原 Job；三次运行各自遇到过期缓存时均有且仅有一次恢复；有效缓存复用、明确 ACL、模糊 403、外部登录链接、200 soft-404、未完成用户名页、路径映射与旧任务配置保持不变。模拟页面未点击 Build。另复跑现有登录、Job 轮询、诊断及全量测试。

## Mac 上最小验证

更新源码后，在原任务点击 **Resume**，保留原有任务与分支。若弹出公司 SSO/MFA，在可见 Chrome 中完成；若未能自动进入登录，可手动运行 `./app-build login --site plugin` 保存会话后，再 Resume 原任务。

如果仍失败，只需提供该原任务最新日志中的 `[JENKINS-TARGET]`、`[JENKINS-ACCESS]` 与最终错误几行（无需 Cookie/Token/密码）；并确认用同一公司账号打开日志中 **精确 Plugin Job URL** 后，是登录页、Job 页还是 Not Found。无需重复提供本地截图下载链接。父 Job 可访问也不能证明子 Job 一定有权限。

本环境未访问公司内网、实际 Mac Keychain 或真实 SSO，也未触发真实构建；离线回归证明工具逻辑已修复，不等于已解决公司真实权限。
