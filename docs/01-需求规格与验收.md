# 需求规格与验收标准（v0.3）

> 范围：在公司许可的 Mac 上并发执行多个**相互独立的** iOS APP 打包任务。以下是用户提供的真实操作规则；地址只指向企业内网。所有会修改仓库或触发 Jenkins 的行为，均在本地运行时发生。本工程没有在企业 Jenkins 完成过真实端到端联调。

## 1. 用户输入、固定配置与机密

| 输入 | 要求 | 示例 |
|---|---|---|
| Plugin GitHub URL | 配置中有默认值，命令行可覆盖 | `https://alm-github.systems.uk.hsbc/mobile/paybybank-ios-plugin` |
| Plugin 源分支 | 必填；不可直接修改 | `develop` |
| Plugin 大版本 | 必填，`Major.Minor` | `1.3` |
| GMX GitHub URL | 配置中有默认值，命令行可覆盖 | `https://alm-github.systems.uk.hsbc/mobile/mobilebanking-global-ios` |
| GMX 源分支 | 必填；不可直接修改 | `develop` |
| 国家 / `ENTITIES` | 默认 `UK`；工具规范化为大写 | `UK` |
| 项目名 | 必填，字符集限英文数字及 `_`/`-` | `PayByBank` |
| GitHub Token | 必须来自 `config.yaml` 指定的环境变量（默认 `GITHUB_TOKEN`） | **绝不放进配置文件** |
| Jenkins Plugin/GMX | Jenkins 父级 URL 配在 `config.yaml` | URL 固定部分 + 当前分支对应 Job 名称 |

示例：输入 Plugin Version=`1.3`，统一时间戳=`202610100030`。

| 派生项 | 值 |
|---|---|
| Plugin 工作分支 | `release/1.3.202610100030` |
| 两个 xcconfig 版本 | `1.3.202610100030` |
| Plugin Jenkins 最后一段 | `release_1_3_202610100030` |
| GMX 工作分支 | `upload/auto202610100030` |
| GMX Jenkins 最后一段 | `upload%2Fauto202610100030` |
| GMX `CUSTOM_FOLDER` | `0_A_UK_PayByBank` |

每个任务只生成一次时间戳并持久化；同一分钟并发启动的其他任务使用**另一个未占用的分钟编码**。这保证名称不冲突，但第二个编码可能比实际时钟略靠后。

## 2. Plugin 阶段（P01—P09）

1. P01 从指定 Plugin 源分支创建**新的本地工作分支**，从源 Commit SHA 保存基线。
2. P02 在 `PayByBankDomainModelPluginKit/ProjectConfigurations/PayByBankDomainModelPluginKit.xcconfig` 精确替换唯一一处 `BUNDLE_VERSION_SHORT`。
3. P03 在 `ProjectConfigurations/PayByBankJourneyPluginKit.xcconfig` 替换唯一一处同名键。不得修改 `BUNDLE_VERSION = 1`。
4. P04 Git Diff 必须只有这两个文件的目标版本值；检测 Git Hook 在提交后引起的变化。
5. P05 Commit + Push 工作分支，必须验证远端 SHA 一致；**不得** Push 源分支。
6. P06 根据 URL 规则等待 Plugin Jenkins 新 Job 被自动发现，不能认为 Job 创建即 Build 成功。
7. P07 兼容首次只有普通 `Build` 的情况：触发初始化 Build；**可能失败**。只有参数化入口随后出现，才能继续。
8. P08 触发 `Build with Parameters`，所有 Jenkins 默认参数保持不变；监控本次明确的 Build Number。
9. P09 从本次 SUCCESS Build，或显式对应的 Callback Build 的 Artifacts 中获取：
   - `build-universal/PayByBankDomainModelPluginKit-<version>.tar.gz`
   - `build-universal/PayByBankJourneyPluginKit-<version>.tar.gz`

完整版本号要一致，例：`1.3.1-alpha.1-SNAPSHOT.2`。**不得把此版本转换为 `1.3.0`，也不得把 `BUNDLE_VERSION_SHORT` 当作依赖版本。** 不能从 Last Successful Artifacts 读取别人的旧产物。

## 3. GMX 阶段（G01—G10）

1. G01 从 GMX 指定源分支创建 `upload/auto<同一时间戳>` 工作分支。
2. G02 在仓库根目录的 `mobile-ci.json` 中用 `group=paybybank-ios-plugin`、`library=PayByBankDomainModelPluginKit / PayByBankJourneyPluginKit` 精确定位**两项**依赖，`version` 直接设为 Plugin 的完整 Artifact Version。
3. G03 在该任务自己的 GMX 仓库**根目录**执行 `./bootstrap.sh`（不是工具根目录）；此脚本更新 `mobile-ci.lock` 及两个 SHA256。
4. G04 验证命令退出码、两个 lock `version`、`sha256`（64 位十六进制），其他锁依赖内容不得变化。
5. G05 确认只准备提交 `mobile-ci.json`、`mobile-ci.lock`；若 bootstrap 还修改其他文件，**停止并人工检查**。不执行 `git add .`。
6. G06 Commit + Push 工作分支；验证真实 Commit 内容和远端 SHA。
7. G07 自动等待 `upload%2Fauto<时间戳>` Jenkins Job 创建。
8. G08 如果是新 Job 的普通 `Build`，按初始化规则处理；参数化入口出现后再启动正式构建。
9. G09 在 `Build with Parameters` 表单仅覆盖以下三项：
   - `ENTITIES`: 国家代码，如 `UK`；
   - `SYNC_UPLOAD`: 勾选 `true`；
   - `CUSTOM_FOLDER`: `0_A_<countrycode>_<projectname>`。

   **其他字段保留 Jenkins 默认值**，包括截图示例 `BUILD_TYPE=Develop`、`SIGNING_REPO_BRANCH=master`。如果控件无法唯一定位，则不点击 Build。
10. G10 追踪明确的 GMX Build Number 直到最终状态。默认最终 `SUCCESS` **只表示 Jenkins 构建成功**，上传的独立成功证明可通过 `upload_success_pattern` 配置检测；没有配置时结果标记 `NOT_INDEPENDENTLY_VERIFIED`。

## 4. 并发、恢复与风险控制（N01—N08）

1. N01 macOS 上多个独立 Worker 进程并发，默认最大 2，配置可调整。
2. N02 Worker 拥有独立 Plugin/GMX 工作目录、Jenkins Context/Build Number、日志、状态与最终报告。
3. N03 SQLite 事务分配唯一时间戳，且为每个**同一任务**设置 `worker.lock`，禁止同时恢复两份。
4. N04 每步记录 `state.json`，恢复跳过已确认完成步骤；发生点击 Jenkins 后的歧义时必须 `NEEDS_ATTENTION`，不可盲目重触发。
5. N05 失败分为 `FAILED`、`TIMEOUT`、`NEEDS_ATTENTION`，日志和截图保留。
6. N06 GitHub Token 不落盘；企业 Nexus 索引与 Chrome 使用公司配置。SSO 的 `auth/*.json` 属敏感文件，必须保护。
7. N07 正式执行一两个小时应可轮询等待；Mac 不休眠、VPN 可用；任务状态可查询。
8. N08 提供 `--dry-run` 无副作用预览；内网真实部署前仍必须用测试分支联调。

## 5. 验收条件

- A01：`--dry-run` 显示的 Plugin / GMX 分支和 Jenkins URL 必须与用户确认的转换规则完全一致。
- A02：Plugin 两处版本号必须一致，Git Diff 不得出现其他内容。
- A03：初始化 Build 失败但进入参数化入口的场景可继续；不能把正式 Build 失败当作初始化失败。
- A04：必须从对应 SUCCESS Build 的两份 Artifact 取得相同的**完整**版本号。
- A05：GMX JSON 两个依赖都必须使用完整 Artifact Version；`bootstrap.sh` 在 GMX 根目录执行，lock hash 自动更新并校验。
- A06：GMX Jenkins 三个指定参数正确；其他默认值不改。
- A07：多个独立 APP 同时运行，既不共享 Git 工作目录，也不混淆 Build 编号。
- A08：同一任务恢复不能重复触发或并发运行；不确定就停止。
- A09：最终报告包含分支、Job URL、Build Number、结果及上传校验状态。
- A10：Nexus 和 SSO 场景联调完成，才可以声称“真实企业端到端通过”。
