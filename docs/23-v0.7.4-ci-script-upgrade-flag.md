# v0.7.4 — 修正 ci-script 升级参数

现场提示：`The 'upgrade' script is not declared in your mobile-ci.json`。v0.7.3 写成了 `ci-script upgrade`，CLI 将 upgrade 当作项目脚本名。此前公司终端提示的升级语法为 `ci-script --upgrade`。

正式 GMX 流程和隔离 Bootstrap Test 均已改为参数列表 `['ci-script', '--upgrade']`；仍在同一工作目录内先升级，再执行 `./bootstrap.sh`。升级失败停止、不新增流程步骤、不放宽 lock 和文件变化保护。

离线测试明确验证 `--upgrade` 参数、命令顺序、失败阻断和十 Worker 并行隔离。原有模拟没有验证公司 CLI 语法，因此先前的通过结果不能证明那条命令语法正确；本次参数依据现场错误及 CLI 输出修正。

本次第一次三轮回归中，第三轮十进程同时创建任务偶发 `PRAGMA journal_mode=WAL` / `database is locked`，因此该轮判定失败。已修正 `store.connect`：先配置 busy_timeout，仅对 WAL 初始化中的 SQLite BUSY/LOCKED 错误重试，最长 30 秒；其他错误直接抛出，初始化失败关闭连接。任务并发上限和事务校验保持原样。

修正后十任务专项连续 20 轮通过，每轮两个十进程集成用例；日志见 parallel-verification-v0.7.4/ten-task-stress.log。重新执行三轮完整回归，每轮 220 项全部通过，编译、Shell 语法和 CLI dry-run 均通过。当前完整日志见 verification-logs/round1.txt 至 round3.txt。公司 ci-script 的真实升级及企业构建仍需现场验证。
