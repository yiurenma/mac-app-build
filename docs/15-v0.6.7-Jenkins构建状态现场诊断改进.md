# v0.6.7 — Jenkins URL 测试：真实页面返回 UNKNOWN 的改进

## 现场反馈（2026-10-10）

用户从本地 Web Console 对 Plugin Build #2 运行只读 URL Test：

- Job HTTP 200，Build History IDs 为 `[1, 2]`；
- #2 Build History 和详情标题均识别为 UNKNOWN；
- `consoleText` HTTP 200，但读取到的内容只有约 401 字节，且不含末行 `Finished:`；
- 页面上可见与 #2 对应的绿色完成图标。

上述情况表示 **识别证据不足**，不能断言 Jenkins 构建失败，也不能断言状态 API 正常。`HTTP 200` 不意味着拿到真实 Console 日志。

## 修复

1. **不再强依赖旧版 `#buildHistory` CSS 容器**：从整页所有 `<a href>` 里，精确筛选属于当前 Job、编号等于 `#2` 的构建链接，然后在其最近的独立行容器检查 SVG/IMG 图标。只认与本编号链接同一行的小图标，禁止跨越包含其他构建编号的共同父容器。
2. 优先解析图标的 `title`、`aria-label`、class 与 SVG `<use>` 的状态资源；如果新 Jenkins 主题只通过 CSS 上色，限定 **可见的、小尺寸、与本 Build 行绑定的 SVG/IMG 图标**，再谨慎识别绿色/红色。中性颜色、多个冲突结果和长条进度条均不得判定成功。
3. Jenkins URL Test 输出 DOM 证据：目标 Build 链接数量、候选记录数量、SVG/IMG 尺寸与 CSS 色值。不能识别时保存当前详情页截图到 `.appbuilder/diagnostics/<site>/<site>-build-N-unknown.png`。
4. `consoleText` 备用检查记录 HTTP 状态、`Content-Type`、末尾字节数。如果 HTTP 200 返回 HTML，则说明响应可能不是预期纯日志，不据此推断成功。
5. Plugin 与 GMX 共用这套检测逻辑。所有 URL 现场测试只读：不点击 Build、不修改 Git、不创建新的流水线任务。

## 如何在 Mac 上验证（无需重跑 Build）

1. 停止旧 Web Console 服务，解压完整 ZIP 到**新目录**。
2. 如需旧任务/SSO 登录态，运行 `Import Previous Data.command` 从旧目录导入 `.appbuilder` 数据，保留旧目录直到验证成功。
3. 双击 `Start APP Builder.command`，确认左下角版本为 **v0.6.7**。
4. 打开 `Jenkins URL Test` → `Plugin`，输入已完成的 Plugin Job URL，Build Number 填 **2**，Expected 选 SUCCESS，点击“打开 Chrome · 测试 Plugin”。如需 SSO，在 Chrome 登录。
5. 看 `[DOM]`、`[ICON]` 与 `[VERDICT]`。如果 UNKNOWN，诊断现在会提供可以定位页面结构的证据，不再只能知道未知。GMX 使用另一入口，操作相同。

本版通过本地真实 Chromium DOM 合成页与离线回归。**公司真实 Jenkins 页面尚未在此环境直接访问，不承诺在所有 Jenkins 主题中立即得到 PASS**。遇到 UNKNOWN，请提供新的诊断文本，特别是 `[DOM]` 和 `[ICON]` 几行（可遮蔽内部 URL）。
