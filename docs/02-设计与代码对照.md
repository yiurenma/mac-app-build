# 技术设计、状态机及逐项代码映射（v0.3）

## 1. 结构与职责

```text
app-build                用户命令入口
install.sh               企业 Nexus / 浏览器安装策略
config.yaml              公共 URL、Jenkins 参数与安全阈值
appbuilder/
  cli.py                  run/login/doctor/status/logs/resume、进程管理
  config.py               YAML 读取、Token 环境变量检查
  versions.py             输入验证、时间戳、分支/Job URL、产物版本解析
  gitops.py               Git AskPass、checkout、精确 commit/push/远端校验
  edits.py                精准改两个 xcconfig、GMX json、lock 检查
  verify.py               根据源 SHA 对最终 Commit Blob 复核
  jenkins.py              Playwright 登录/触发/轮询/Callback/Artifacts
  store.py                SQLite 任务创建、步骤状态 JSON 持久化
  runner.py               Plugin -> GMX 顺序编排、失败归类与结果
  __main__.py             python -m appbuilder
```

## 2. 完整执行状态

```text
INIT / QUEUED
  PLUGIN_CHECKOUT
  PLUGIN_EDIT
  PLUGIN_PUSH
  PLUGIN_JENKINS
  GMX_CHECKOUT
  GMX_EDIT
  GMX_BOOTSTRAP
  GMX_PUSH
  GMX_JENKINS
FINISHED / SUCCESS
```

每步执行后 `store.complete()` 把步骤名称写入 `state.json`；步骤中的关键值，例如源 SHA、Push SHA、Artifact Version、Jenkins baseline / number / result，会在完成步骤之前通过 `patch_runtime()` 更新。恢复时跳过已完成步骤。`worker.lock` 用 macOS 的 `fcntl.flock` 锁住整个任务，防止两个进程同时恢复同一任务。

## 4. 恢复及幂等性设计

- **Git：** 先记录源 Commit SHA，再更改文件，Push 前核对允许文件、总变动行数及最终 Blob。Git Hook 修改“允许文件”的内容，也会经 `verify.plugin_commit`/`verify.gmx_commit` 阻止 Push；Push 后远端 SHA 必须一致。若崩溃发生在 Push 后、记录状态前，尝试根据目标分支、Commit message、父 SHA 和 Diff 恢复。
- **Jenkins：** 点击 Build 前先保存该 Job 当前 Build Number 集合（baseline）；点击后只接受唯一新增 Build 编号。若进程在点击前后不确定时中断，恢复优先读保存的编号/baseline；无法安全判断时暂停，不触发第二次。
- **GMX bootstrap：** 上一次 bootstrap 若跑到一半，恢复时可以重跑，但仍以最终 JSON/lock 验证和 Diff 白名单为准；若意外变更其他文件，不提交。
- **最终报告：** 先原子写 `result.json`，再把任务数据库状态设为 `SUCCESS`，避免出现已成功但报告缺失的状态。

## 5. 不在离线环境里假装已完成的验证

- Playwright 的 Chrome 通道可启动，不代表企业 SSO 可以持久化；必须 Mac 现场验证。
- Jenkins 的菜单项、参数控件、Callback 展示文本、Artifact 目录可能随 UI/插件版本变化；现有模拟测试不能替代真实 DOM 验证。
- 本工具不使用 Jenkins API；如果页面不能安全识别，会停止并截图，而不是任意猜测。
- 内部 Nexus 代理的证书、认证和 Python 包缓存依公司政策配置；离线测试未连接 Nexus。
- 上传完成证明如果没有 `upload_success_pattern`，最终只声明 Jenkins Build 成功，不声称已通过独立验证。

## 6. 需要维护时如何改

- Git 分支命名规则：优先修改 `versions.py`，同步 `test_job_name_conventions` 与需求文档。
- Jenkins Job URL：改 `config.yaml` 父路径和 `versions.job_urls()`；保留固定输入分支对应关系。
- Jenkins 参数控件变化：优先配置 `config.yaml > jenkins.gmx_fields` 三个选择器；联调证实确实改变后再改 `jenkins.py`。
- Plugin xcconfig 路径：改 `edits.XCCONFIGS`，保留唯一性和 Blob 校验测试。
- lock 更新行为变化：不要手改 SHA；先检查 GMX 仓库自己的 `bootstrap.sh`，再决定是否调整 lock 的语义保护策略。
