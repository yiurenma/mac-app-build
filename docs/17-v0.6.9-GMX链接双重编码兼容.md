# v0.6.9 — GMX URL 双重编码与首轮初始化

## 根因

公司 Jenkins 可将 GMX 分支 `upload/UKPBB-203745-V2` 的 URL 显示成 `upload%252FUKPBB-203745-V2`，而较早的诊断器只接受 `%2F`，导致用户点击测试时在启动浏览器之前报 `Job 名称只允许 Jenkins 的 %2F 分支编码`。

## 修复

- `parse_target` 接受 `%2F` 或 `%252F`，大小写均可；不自动解码，不破坏用户原始 Jenkins URL。
- 继续拒绝任意 percent 序列、双重路径遍历编码、用户信息、HTTP、非预期域名及跨 Job URL；保留手输 Build 编号与路径一致性检验。
- 诊断日志标记检测到双重编码，避免误认为脚本更改了路径。
- Web 上明确说明 GMX 只读测试不会执行第一次初始化 Build。

## GMX 实际流程（与 Plugin 不同）

1. 新 Job 首次仅有 `Build` 按钮：必须触发第一次 Build。
2. 第一次 Build 可能显示 `Build disabled: ENTITIES or BUILD_TYPE is empty`，属于参数化初始化过程，并不要求第一次 Build 成功。
3. 等待首次 Build 结束、页面出现 `Build with Parameters`；正式任务只在入口就绪后填参数、启动正式 Build。
4. 直接追踪正式 Build #2；不使用 Plugin 的 Trigger/Callback 转交模型。

**注意**：只读诊断不点击 Build、不会初始化 Job。若用户从真实 Jenkins 复制 URL，优先原样粘贴，不主动将 `%252F` 替换为 `%2F`。

本版本的 URL 解析与流程边界通过离线测试；企业 Jenkins / SSO 尚需现场验证。
