# v0.6.4 Jenkins 快速确认

## 真实问题

用户截图：Plugin Trigger #1 关联 Callback #2，#2 Jenkins 页面已经显示 SUCCESS；Web Console 仍在 `PLUGIN_JENKINS` 阶段报告状态尚未确认，旧实现依赖 Chrome 页面渲染的 `document.body.innerText`。

## 修复策略

1. 读取已登录 Playwright browser context 的 HTTP `/consoleText` 原始响应；保留 Cookie，不请求 Jenkins `/api/json` 等 REST API。
2. 严格使用最后一行的 `Finished: <终态>`，只解析当前编号 Build，不读取历史 Build；默认间隔 5 秒。
3. 只有明确成功/失败后才继续；在控制台不能完整读取时，每 45 秒备用检查当前 Build 页面。
4. 构建 Trigger 与 Callback 仍必须经 Source 关联；不能误用其它 Build。
5. `result_poll_seconds` 以任务隔离配置；原有 `poll_seconds` 保留用于备用检查。

## 局限

- 5 秒只是检测周期，不会让 Jenkins 构建提前完成；遇到网络/SSO延迟可能更久。
- 实际企业 Jenkins 的 `/consoleText` URL 可访问性仍待用户 Mac 验证；本地采用离线 mock 与 HTTP 接口测试。
- 已运行的旧 Worker 不会热加载新代码；先停止旧 Worker、更新、Resume 原任务（不重复 Build）。
