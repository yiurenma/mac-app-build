# v0.6.1 — Web Console 稳定性修复与验证

## 修改清单

1. 新增纯标准库 `appbuilder/launcher.py`，在安装前检测现有 `127.0.0.1` Web Console：已运行则只打开页面；空闲才启动；被其他应用或旧版占用时提示退出。不会跟随其他服务的 HTTP 重定向。
2. 增加 `/api/health`，返回非敏感的应用标识和版本号。其他 API 安全规则维持。
3. 双击脚本复用现有 Console；`web --update` 遇到本地修改、Git 更新失败或 30 秒更新超时会继续启动原版本；`run/resume --update` 仍拒绝本地覆盖或更新失败。
4. 浏览器侧依据实际 `location.host` 显示本地端口。
5. 在构建任务详情中提供 Plugin Trigger、Plugin Callback、GMX Build 的 Jenkins HTTPS 深链接；构建编号只读取原有 `state.json`，不访问 Jenkins API，也不暴露原始任务参数/凭据。
6. SQLite `with` 事务退出并不自动关闭连接，现改用 `closing(connect())`，降低长期运行 Web 服务的连接资源风险。

## 验收方式

- 执行 `python3 -m unittest discover -s tests -v`，覆盖原有流程、新启动器/本地 HTTP、无外网情况下的更新回退、Callback 深链接和 SQL 连接关闭。
- 对本地 HTTP `/api/health` 实际请求应返回 `app=mac-app-builder` / `version=0.6.1`。
- 双击启动、Mac Keychain、企业 SSO 与真实 Jenkins 仍需在公司 Mac 联调。
- 多次双击：如旧版本（无 `/api/health`）仍占用端口，提示先关闭旧版后再次启动；不会强制杀死旧服务或 Worker。
- 此版本未进行公司生产环境构建，不应据此宣称端到端成功。
