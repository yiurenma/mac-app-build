# v0.6.6 — Plugin / GMX Jenkins URL 现场单元测试

这个入口专门用于验证已经存在的 Jenkins Build 的结果识别，不必重新构建 APP。

## 使用方法（Web Console）

1. 双击 `Start APP Builder.command`，打开本地 Web Console。
2. 点击左侧 **Jenkins URL Test**，选择 **Plugin Jenkins · 单元测试** 或 **GMX Jenkins · 单元测试**。
3. 输入对应分支 Job URL（例如 `…/job/release_1_3_202610101332/`）或具体 Build URL（例如 `…/2/`）。若仅填写 Job URL，可以设置 Build Number = 2；若 Build URL 自带 `2`，不要填矛盾编号。
4. Expected Result 选择 SUCCESS（绿色勾）或其他预期终态。
5. 点击对应的 **打开 Chrome · 测试**。程序启动可见的 Chrome，如出现 SSO/MFA 页面，可直接在 Chrome 人工登录，最多等待 180 秒。*不需要提前保存 Jenkins 密码。*
6. Web 页面每秒刷新测试日志。结束时显示 `PASS` / `FAIL` / `UNKNOWN`，并列出精确 Build #、Build History 状态、详情页图标状态、必要时的 consoleText 末行及 HTTP 结果。

## 只读检查顺序

1. 从 URL 识别 Plugin 或 GMX Jenkins 域，严格核对公司配置的父 Job。
2. Playwright 启动可见 Chrome，导航到 Job；如需登录，允许人工完成 SSO，再回到原 Job。
3. 从 Build History 精确找到指定 Build # 的状态图标（不借用别的构建的绿色勾）。
4. 打开该 Build # 的详情页，检查标题旁的状态图标。
5. 仅当图标无法判定时，短超时获取 `consoleText` 的最终 `Finished:` 行；状态冲突直接返回 UNKNOWN。
6. 给出预期值、实际值和下一步建议。

**不会点击** `Build`、`Build Now`、`Build with Parameters`；也不会操作 Git、更新 `mobile-ci.json`、创建构建任务或者 Resume。

## CLI（可选）

```bash
./app-build diagnose-jenkins 'https://<Plugin-Jenkins>/job/<branch>/2/' --expected SUCCESS
./app-build diagnose-jenkins 'https://<GMX-Jenkins>/job/<branch>/2/' --expected SUCCESS
```

CLI 默认也会打开可见 Chrome，支持手动 SSO，实时打印诊断日志。诊断结果按站点保存于 `.appbuilder/diagnostics/plugin/last-result.json` 和 `.appbuilder/diagnostics/gmx/last-result.json`。

## 无法 git pull 的用户：整包替换

请下载完整 ZIP，**解压到新目录**。不要删除原版本目录中含有 `.appbuilder` 的任务数据。新目录可以双击 `Import Previous Data.command` 并在 Finder 选择旧目录，迁移旧任务、日志和保存的登录会话；原目录不会删除。再双击 `Start APP Builder.command`。如果原版本仍有 Worker 在运行，先停止旧 Worker，避免两个版本操作相同任务。

## 结果含义

- `PASS`: 当前 Build 的实际 Jenkins 终态等于你输入的预期值；例如 #2 显示绿色勾且预计 SUCCESS。
- `FAIL`: 明确终态与预期不同；例如预期 SUCCESS，但当前 #2 为 FAILURE。
- `UNKNOWN`: 登录、页面、图标或日志无法确定真实结果，或者 Build History 和详情页出现冲突；不能凭颜色猜测成功。

Plugin 的 SUCCESS 不自动代表两个 Artifact 版本已核对；GMX 的 SUCCESS 也不自动代表上传结果已独立验证。

> 本版已通过离线自动化、真实 Chromium DOM 和本地 HTTP 路由测试；企业 Jenkins 和企业 SSO 尚需 Mac 内网现场验证。
