# v0.7.0 现场测试说明

## Bootstrap Test

- 分支输入示例：`upload/UKPBB-203745-V8`
- 使用现有 GMX GitHub URL、Mac Keychain 中的 PAT；只读取远端分支，不上传。
- 沙箱目录：`.appbuilder/live-tests/bootstrap-<随机ID>/gmx`，不修改原构建目录。
- 顺序：shallow clone → 确认 bootstrap.sh 可执行 → `./bootstrap.sh` → 检查 Git status → 展示退出码/变更。
- 每次运行会访问公司内部依赖服务（如果脚本需要）；可能耗时，日志会显示心跳，不承诺在离线环境完成真实 bootstrap。
- 注意本测试确实执行所选分支中的 Shell 脚本，应使用可信的公司分支。

## GMX Jenkins Build Test

- 分支示例：`upload/UKPBB-203745-V8`，支持可选的 Job URL。粘贴 Job URL 后会验证它属于配置的 GMX Jenkins 父级、且确为相同分支。
- 勾选真实触发确认后：打开 Chrome → 人工 SSO（如需要）→ 识别 Build 模式 → 首次普通 Build（仅在非参数化时）→ 等待参数页 → 填入国家及参数 → 触发正式 Build → 跟踪指定正式 Build 的 SUCCESS/FAILURE。
- `ENTITIES=UK`、`BUILD_TYPE=Develop`、`SIGNING_REPO_BRANCH=master`、`SYNC_UPLOAD=true`、`SKIP_TEST=true`、`FORCE=true`、`KEEP_ALIVE=false` 为默认值，可修改。
- 不执行 Plugin 操作、不修改正式任务、不会 Git Push；会创建 Jenkins 构建，运行时间取决于远端任务。
- 默认 URL 依次尝试 `%2F`、`%252F` 编码；若 Jenkins 使用特殊重写，请在可选字段粘贴浏览器的 Job 地址。
- 已完成 `#1` 初始化时若 Jenkins 显示参数化入口，会跳过首个 Build，避免无意义重复。
- 失败或浏览器状态不明会停止，而不是盲点 Build。中断时先检查 Jenkins 真实构建列表，避免重复启动。
- Jenkins SUCCESS 不代表下游外部 Upload 经独立核实；请核对对应 Job 与公司上传目标。

## 日志与限制

`.appbuilder/live-tests/logs/<id>.log` 持续写入脱敏后的日志；Web Console 显示最近 1000 行。原来的只读 Plugin/GMX Jenkins URL Test 保持不变。集成测试使用模拟浏览器和虚拟仓库，不能替代企业网络端到端测试。
