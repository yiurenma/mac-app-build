# 三轮代码审查与自测报告（v0.3）

## 结论与边界

**结论：** 已对 v0.2 基线执行三轮“需求清单 → 流程图 → 实现逐项对照 → 增补/修复 → 自动化回归”的审查，形成 v0.3。最终版本重复运行 **3 轮完整离线回归，每轮 30 项测试全部通过**，语法编译、Shell 语法检查及 `--dry-run` 均退出码 0。

**边界：** 这里没有企业 Nexus/SSO/内网 Jenkins 的可用访问条件；因此全部测试为离线/本地模拟，**不代表 Plugin 和 GMX 两条 Jenkins Pipeline 已真实打包成功**。具体现场测试单独列于 `05-企业内网联调清单.md`。

## Round 1：对照用户需求、输入/认证、任务状态

- 审查方式：逐条比对输入/派生版本/源分支/Token/精确 Commit 的要求与 `cli.py`、`versions.py`、`gitops.py`、`store.py`、`runner.py`。
- 发现并修复：
  1. 原版 `config.yaml` 虽允许自定义 `token_env`，AskPass 仍硬编码读取 `GITHUB_TOKEN`；改为从配置选定的环境变量读取，向 Git 子进程通过短期 `APP_BUILDER_GIT_TOKEN` 传递。
  2. 原版后台父进程在启动后写 `RUNNING`，可能覆盖极快结束的 Worker 状态；改为状态/PID 均由 Worker 自己维护。
  3. 任务目录创建如果在数据库提交之后失败，会留下无法恢复的 `QUEUED` 行；改为目录初始化及 DB 预留在同一事务内，失败回滚并清理。
- 验证：原有 13 项测试仍通过，并增加可配置 Token/错误提示/数据库失败回滚等测试。

## Round 2：Jenkins 页面、Build 状态机、Artifact 关联

- 审查方式：将截图中的“初次普通 Build 可能失败 → 出现 Build with Parameters → 正式 Build 成功 → Callback → Artifact”转换为模拟 Jenkins 页面状态机并对照 `jenkins.py`。
- 发现并修复：
  1. 原版可能只读取 `.../<BuildNumber>/artifact/` 首层链接，漏掉 `build-universal/` 子目录中的 tar.gz；改为**只在指定 Build 的 Artifact 根目录之下**有界遍历子目录。
  2. 原版 Callback 只基于横跨多行的宽松正则匹配；改为按 Jenkins 构建卡片解析 `Manual Callback ← Source #n`，多个候选立即停止。
  3. `mode()` 不能仅因页面正文提到 `Build Now` 就认为存在可执行入口；改为依据可操作的命名链接确认。
  4. 构建日志中的 `Finished: SUCCESS` 不能来自中间输出/引用；改为仅认可最终非空状态行，避免假成功。
- 验证：独立构造模拟页面与 Build 序列，覆盖初始化 FAILURE 后继续、源 Build/Callback 对应、不重复触发、多候选拒绝、跨 Job 链接排除、嵌套 Artifact 目录。一次测试夹具错误把“直接参数化构建 #1”模拟为初始化 FAILURE，已修正夹具后通过；没有掩盖这个中间失败。

## Round 3：多进程、安全、Nexus、报告一致性

- 审查方式：检查真实独立 Python 子进程、Worker 锁、公司 Nexus 安装策略、企业 GitHub PAT 指引、GMX 参数控制、最终报告顺序。
- 发现并修复：
  1. 为单个任务加入 `fcntl.flock` 互斥锁，允许两个**不同任务**同时运行，但同一任务禁止双 Worker 并发恢复；附真实 subprocess 并发测试。
  2. `install.sh` 增加对 `install.extra-index-url` 的检查，降低额外公网索引的配置遗漏。
  3. 缺少 Token 时不再错误地只指引到公共 `github.com`；改为从仓库 URL 推导内部 Enterprise GitHub 的 `/settings/tokens`，提示按公司可用 PAT 类型和权限申请。
  4. `result.json` 先写入再设置任务 `SUCCESS`，避免标记成功后生成报告中断。
  5. GMX 表单的 `ENTITIES`、`SYNC_UPLOAD`、`CUSTOM_FOLDER` 的精确填写/其他默认参数不改变，增加模拟控件测试。
  6. 国家输入统一规范化为大写，例如 `hk` → `HK`，避免 Jenkins 选项值/文件夹目录名不一致。
- 验证：最终 30 项离线测试可重复执行；实际双子进程测试在不同目录同时持有 Worker 锁。

## 仍需改进的地方（未被离线测试覆盖）

1. **真实 Jenkins DOM**：实际企业 Jenkins 可能使用与模拟不同的参数类型/菜单结构；优先用 `config.yaml` 的 CSS 选择器现场校准。
2. **Jenkins 触发歧义**：浏览器在点击后崩溃且无法唯一识别 Build Number 时，设计为**人工确认后继续**，不会自动重试；这是为了防重复触发而保留的限制。
3. **Artifact Hash 真实性**：离线验证 lock 中的 hash 为有效 64 位十六进制及 `bootstrap.sh` 返回码，但只有企业制品仓库下载/解析才能证明它对应实际产物。
4. **长期稳定性与 Mac 睡眠**：`caffeinate -i` 不能防止所有关盖、VPN 中断和安全策略带来的断线；需长时间真实测试。
5. **上传最终成功判定**：无独立成功日志模式时，报告只保证 Jenkins Build 结果是 SUCCESS，不保证外部上传被独立验证。
6. **企业 Python 依赖版本复现**：当前 `requirements.txt` 为版本区间而非经批准的哈希锁文件。生产部署可在公司 Nexus 中选定并锁定版本后增加哈希校验。

**发布判断：** v0.3 属“离线逻辑回归通过 / 现场联调待完成”。完成 `05-企业内网联调清单.md` 前，不标注为“生产可用”或“APP 已经成功打包上传”。

- 修改：新增 `appbuilder/pip_sources.py`，按有效 pip 配置校验全部主/备用索引；允许公司 HTTPS Nexus 域名、保留现有 `global.cert` / `PIP_CERT` / 认证设置；拒绝公网 PyPI、HTTP 与未明确批准的陌生主机。不安装、升级 pip 或改写 pip.conf。
- 修改：`install.sh` 不再要求手动覆盖 PIP_INDEX_URL；继续仅在项目虚拟环境内安装 Playwright 和 PyYAML；沿用企业 Chrome。
- 回归：增加双企业 Nexus、env 覆盖、公网索引、HTTP、域名伪装、多个备用索引、凭据不回显等离线用例；同步修复旧断言及并发测试的偶发启动等待不足。

## v0.4.2 — 现场真实 Plugin Trigger/Callback 行为修复

- 实际截图显示：Plugin Jenkins #1 已成功（`Manual Trigger → build will be created soon`），#2 已开始（`Manual Callback ← Source #1`），Worker 仍每隔若干秒显示 #1 `RUNNING`。
- 根因：`wait_result` 仅支持 `Finished: ...` 最后一行和 Jenkins 旧版构建状态图标；新版 Jenkins 的 SVG 状态标记、下游关联 Callback 未在源构建监控循环中处理。
- 修复：新旧状态 SVG 精确识别；Plugin 源 Build 支持 `watch_callback=True`，使用同一 Job 的 Source 编号关联来安全转接下游监控；状态持久化以支持旧 Task Resume。
- 安全条件：只跟踪唯一明确关联的 Callback；#2 失败会停止；GMX 不参与源 Callback 判断；失败状态优先于关联回调；禁止重复触发。
- 补充测试：旧 Task 恢复、Source→Callback→Artifacts、图标识别、失败优先级、Callback 失败阻断，三轮离线回归。企业网络实测仍待完成。


## v0.4.3 新分支 Job 自动发现：10 秒间隔

- 现场截图中的「已等待 2s」是累计耗时，历史实际重试间隔为 45s。
- 新增 `jenkins.discover_poll_seconds`（默认 10s），仅影响 `wait_job`；其他 Build 轮询仍由 `poll_seconds` 控制。
- HTTP 404 表示该新分支 Job 还未出现，等待自动扫描直到 `discover_timeout_minutes`；HTTP 401/403 立即报错。
- 新增模拟检查：连续 404 后出现、403 立即停止、持续 404 超时，确保间隔与次数正确、不会在 404 时触发 Build。
- 自动化回归记录见 `docs/verification-logs/round*.txt`；不代表已在公司 Jenkins 实测。
