# 定时任务（Schedules）

按 cron 表达式自动创建构建。**不改变任何现有构建流程**：到点时调用的就是 Web 页面「Start build」按钮背后的同一个 `create_build()`，所以参数校验、Keychain 凭据、环境检查、并发上限全部沿用。

## 使用

1. 终端运行一次 `./app-build scheduler install`：安装 macOS LaunchAgent，登录 Mac 后自动运行、崩溃自动重启，并用 `caffeinate -i` 防止空闲睡眠。
2. 打开 Web Console 的 **New build** 表单，照常填好参数（含高级参数），在底部打开 **保存为定时任务**，填写名称和 cron，页面会实时预览接下来 5 次运行时间，然后点 **Save schedule**。定时任务用的就是这一份表单，以后表单新增字段或修改默认值，定时任务自动跟着生效，无需另外维护。
3. 左侧 **Schedules** 列表里可以 停用/启用、立即运行、编辑（会把参数回填到 New build 表单）、查看运行记录（可跳转到对应构建日志）、删除。已保存的计划保留创建时的参数值，之后修改默认值不会改动它们。

其他命令：`./app-build scheduler status | run | uninstall`。`run` 是前台运行（LaunchAgent 用它），调试时可手动执行。日志：`.appbuilder/scheduler.log`。

## 行为约定

| 场景 | 行为 |
| --- | --- |
| 电脑睡眠/关机期间错过了多次 | 醒来后**只补跑最近一次**，运行记录里注明"错过 N 次"。 |
| 到点时并发已满（`build.max_parallel`） | **排队，不丢弃**；有空位后按计划时间先后启动。定时和手动构建共用名额。 |
| 同一个时间点 | 数据库唯一约束保证只会触发一次，调度器重启也不会重复。 |
| 启动失败（环境检查、Token 等） | 记录为 FAILED 及原因，不影响其他计划，下一个时间点继续尝试。 |
| 修改 cron / 重新启用 | 从当前时间重新计算，不补跑停用或编辑期间的时间点。 |
| 无人值守 | 默认不弹 Chrome 窗口（可在计划里勾选显示）。 |
| 最小间隔 | 默认 30 分钟（`config.yaml` → `build.schedule_min_interval_minutes`），避免误填 `* * * * *`；每次运行都会新建分支和 Jenkins 构建。 |

## cron 语法

5 段：分 时 日 月 周。支持 `*`、列表 `1,15`、范围 `9-17`、步长 `*/10`、`MON-FRI`、`JAN`，以及 `@hourly @daily @weekly @monthly`。日和周同时限定时按经典 cron 取"或"。时间为 Mac 本地时区。

## 安全

- 计划只保存**非机密**的构建参数模板；账号、密码、GitHub Token 一律拒绝保存，运行时使用 Mac Keychain 中已保存的凭据。
- GitHub Token 需要保存在 Keychain（在 New build 表单里填写一次即可）。LaunchAgent 读不到终端里 `export` 的环境变量。
- 接口沿用现有的 Host / Origin / CSRF 校验，只监听 127.0.0.1。

## 限制

- Mac 睡眠或合盖时任何程序都不会运行（醒来后补跑最近一次）。需要不错过，请保持开盖并接电源。
- LaunchAgent 在用户登录后运行（需要读取 Keychain）；注销后不会触发。
- 每次运行都会创建新的 `release/…`、`upload/auto…` 分支和 Jenkins Job，暂无自动清理。

## 磁盘占用与清理

每个任务都会把 Plugin 和 GMX 两个仓库完整克隆到 `.appbuilder/runs/<任务ID>/plugin` 和 `gmx`。任务成功后这些工作副本不会再被用到（SUCCESS 任务不能恢复），但此前没有任何清理，定时任务每次运行都会多出两份完整仓库。

- 查看并清理：`./app-build cleanup`（只预览，列出每个任务占用的空间）；确认后 `./app-build cleanup --apply`。
- 只删除 `plugin/`、`gmx/` 两个文件夹；**日志、截图、state.json、result.json 永远保留**。
- SUCCESS 任务立即可清；其他状态（FAILED / NEEDS_ATTENTION / TIMEOUT / INTERRUPTED）保留 7 天以便恢复，可用 `--keep-days N` 调整。正在运行的任务永远不会被清理。
- 调度器每小时（启动时也会立即执行一次）自动清理**由定时任务产生**的任务；手动构建只通过上面的命令清理。
- `config.yaml` 的 `build` 下可选：`auto_cleanup_scheduled_workdirs: false` 关闭自动清理；`workdir_retention_days: 7` 调整失败任务保留天数。
- 已清理的任务目录里会有 `.workdirs-removed` 标记；未成功的旧任务被清理后无法再 resume，需要重新创建。
